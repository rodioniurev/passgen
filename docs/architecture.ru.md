# Устройство программы

[← к README](../README.ru.md) · [English version](architecture.md)

Документ для тех, кто хочет разобраться в коде или что-то в нём поменять. Здесь описано, как устроена программа, и — отдельно — какие неочевидные вещи выяснились на практике. Комментарии в коде написаны по-русски; тексты интерфейса лежат в [`src/Loc.cs`](../src/Loc.cs).

## Общая картина

PassGen — один процесс на WinForms (.NET Framework 4, язык C# 5). Потоки:

| Поток | Что делает |
|---|---|
| Основной (STA) | Значок в трее, окно генератора, справка, плашка. Всё, что трогает интерфейс и буфер обмена. |
| Поток хука | Глобальный перехват клавиатуры (`WH_KEYBOARD_LL`) с собственным циклом сообщений. Нужен только для `Right Alt + P/V`. |
| Поток ожидания | Ждёт именованные события «повторный запуск» и «закрыться». |
| Рабочие потоки ввода | На каждый быстрый ввод — свой короткий поток, который печатает символы. |

```text
 клавиатура ──► KeyHook (поток хука) ──► BeginInvoke ──► TrayApp.QuickType / QuickPaste (основной поток)
                                                              │ генерация, запись в файл, буфер
                                                              ▼
                                                        TypeAsync (рабочий поток)
                                                              │ ждёт отпускания Alt/Shift, печатает через SendInput
                                                              ▼
                                                        плашка Toast (основной поток)
```

## Файлы исходников

| Файл | Что внутри |

| `AssemblyInfo.cs` | Название, версия, авторские права. |
| `Native.cs` | Все объявления WinAPI (P/Invoke) и структуры `INPUT`, `MSG`. |
| `Loc.cs` | Локализация: таблица переводов (английский, испанский, русский), определение языка, формы множественного числа. |
| `Settings.cs` | Настройки и чтение/запись `PassGen.ini`. |
| `Gen.cs` | Генератор паролей, оценка стойкости. |
| `Platform.cs` | `Storage` (дописывание в файл), `Clip` (буфер обмена), `Autostart` (реестр). |
| `QuickInput.cs` | `Win` (мелкие утилиты окон), `Typer` (ввод символов), `KeyHook` (перехват клавиш). |
| `FocusKeeper.cs` | Запоминает окно, куда вернуть фокус, и надёжно передаёт фокус окнам. |
| `PopupForm.cs` | Окно генератора. |
| `HelpForm.cs` | Окно справки по клавишам. |
| `Toast.cs` | Плашка «Скопировано», не отнимающая фокус. |
| `TrayApp.cs` | Значок и меню, связывает всё воедино; сценарии быстрого ввода. |

## Запуск и жизненный цикл

- `Program.Main` создаёт именованное событие `PassGen.Wake`. Если оно уже существовало, значит программа запущена: второй экземпляр сигналит первому (тот открывает окно) и завершается. Так работает «один экземпляр на сеанс».
- `PassGen.Quit` — второе событие: `PassGen.exe /exit` взводит его, и работающая копия корректно выходит (`TrayApp.Quit`: останавливает хуки, убирает значок, чтобы в трее не оставался «призрак»).
- `/autostart` — запуск без окна (так стартует автозапуск).
- `TrayApp` — это `ApplicationContext` без главной формы. Порядок в конструкторе: настройки → язык → окно генератора (с заранее созданными дескрипторами, чтобы открывалось мгновенно) → `FocusKeeper` → хук клавиш → меню и значок → поток ожидания событий.

## Локализация (`Loc.cs`)

- Все тексты интерфейса лежат в одной таблице `Loc.Table`: строка на ключ, колонка на язык (`ключ | en | es | ru`). Чтобы добавить язык, нужно дописать код в `Loc.Codes`, название в `Loc.Names` и одну колонку.
- `Loc.Init(setting)` принимает `auto` или код языка. `auto` (и любое незнакомое значение) разрешается через `Loc.Detect()` — двухбуквенный код `CultureInfo.CurrentUICulture` (язык **интерфейса** Windows), если он поддерживается, иначе английский.
- `Loc.T(key, args…)` возвращает строку на текущем языке; если перевода нет — английскую, а если нет и её — сам ключ (так опечатка видна, но не фатальна). `Loc.Plural(n, key)` выбирает форму слова (`character|characters`, `знак|знака|знаков`).
- Формы строят весь свой текст в конструкторах, поэтому **при смене языка окно генератора создаётся заново** (`TrayApp.SetLanguage`): старое окно уничтожается (при этом снимается регистрация `Ctrl + Alt + P`), новое регистрирует её снова; окно справки закрывается; тексты меню и подсказка значка обновляются. Перезапуск не нужен.
- Вёрстка переживает разную длину текстов: флажки берут свой предпочтительный размер, подпись «минимум/ровно» рассчитана на более длинный из двух текстов, а колонка клавиш в справке — на самое длинное название клавиши.
- `tests/LocalizationTests.ps1` сторожит таблицу: полнота, совпадение подстановок, отсутствие опечаток в ключах, подсказка значка ≤ 63 знаков на каждом языке.
- Язык хранится в `PassGen.ini` как `lang=auto|en|es|ru`.

## Генератор (`Gen.cs`)

1. Алфавиты: строчные, заглавные, цифры, спецзнаки (из списка пользователя, очищенного от букв, цифр, пробелов, дублей). В режиме «Удобно вводить» из алфавитов убираются `0 O 1 l I |`, а из спецзнаков — «трудные» (`| \ / ` ' " ~ ^ < > ( ) [ ] { } ; : . ,`). Если после очистки список спецзнаков пуст, берётся запасной: `!@#$%^&*-_=+?` (в режиме «Удобно вводить» — `!@#$%&*-_+=?`). В режиме блоков из спецзнаков убирается `-` — это разделитель.
2. Обязательные знаки: по одному из каждого включённого набора и ещё `MinSymbols` спецзнаков. Если пароль слишком короткий для всех обязательных знаков, лишние спецзнаки отбрасываются.
3. Остальные позиции заполняются из общего пула. В режиме «Удобно вводить» спецзнаки в пул не входят, поэтому их ровно `MinSymbols`.
4. Знаки перемешиваются (Фишер — Йетс). «Начинать с буквы»: если первым оказался не буквенный знак, он меняется местами со случайной буквой.
5. Блоки: размеры подбираются так, чтобы общая длина с дефисами в точности равнялась заданной, а средний размер блока был ближе к 4,5 знака (`BlockSizes`).
6. Случайные числа — `RandomNumberGenerator`; число в диапазоне `[0, n)` берётся отбрасыванием «хвоста» (rejection sampling), поэтому смещения вероятностей нет.
7. Оценка стойкости: `число случайных знаков × log2(размер пула)`. В режиме «Удобно вводить» считается точнее: знаки из алфавита без спецзнаков + выбор позиций и значений спецзнаков (`Log2Choose`).

Метод `Gen.Make(Settings, out double bits)` не зависит от интерфейса — на нём построены [автотесты](../tests/GeneratorTests.ps1).

## Настройки (`Settings.cs`)

Простой INI (`ключ=значение`), читается один раз при старте, пишется при каждом изменении в окне. Все значения при чтении ограничиваются допустимыми диапазонами. Путь к файлу паролей по умолчанию — рядом с exe.

## Окно генератора (`PopupForm.cs`)

- Создаётся один раз и затем только показывается и прячется. У окна и всех элементов заранее создаются дескрипторы (`Prepare`), поэтому показ занимает десятки миллисекунд.
- Без рамки (рамку в 1 пиксель даёт отступ формы), тень — `CS_DROPSHADOW`. Размеры считаются через `S()` по системному DPI; в манифесте `dpiAware = true`, иначе Windows размывала бы окно на экранах с масштабом.
- Любое изменение настроек вызывает `Changed()`: чтение элементов → сохранение INI → новый пароль. Флаг `loading` не даёт событиям зацикливаться при программной установке значений.
- Окно скрывается при потере активности (`OnDeactivate` → `Dismiss`). Клик по значку в трее тоже отнимает у окна фокус, поэтому `TrayApp.TrayClick` использует окна времени (500 и 300 мс), чтобы отличить «открыть» от «закрыть».
- Горячая клавиша `Ctrl + Alt + P` регистрируется обычным `RegisterHotKey` на дескриптор окна.

### Фокус (`FocusKeeper.cs`)

Проблема: после клика по значку в трее фокус получает панель задач, и когда окно PassGen закрывается, Windows не всегда возвращает его программе, где вы работали — курсор «пропадает».

Решение:

- `FocusKeeper` подписан на `EVENT_SYSTEM_FOREGROUND` (`SetWinEventHook`, без внедрения DLL, события своего процесса пропускаются) и помнит последнее «настоящее» окно. Окна оболочки (панель задач, меню, переключатель задач и т. п.) в список не попадают.
- Окно запоминает `returnTo` при показе. По `Enter`, `Esc`, повторному нажатию сочетания и повторному клику по значку (`DismissAndReturn`) фокус возвращается в это окно. Простое скрытие по потере активности (`Dismiss`) фокус не трогает — пользователь сам кликнул в другое окно.
- Если Windows не отдала фокус окну, курсор может оказаться на форме, а не в поле описания: таймер `focusTimer` несколько раз с паузой ставит курсор в поле.
- Принудительная передача фокуса через `AttachThreadInput` используется **только для возврата** фокуса. Для показа собственного окна её использовать нельзя: подключение к потоку чужого окна вызывает деактивацию, и окно тут же прячется само.

## Быстрый ввод

### Перехват клавиш (`KeyHook`)

Нужен глобальный хук `WH_KEYBOARD_LL`: `RegisterHotKey` не различает левый и правый Alt и не позволяет «съесть» букву так, чтобы она не дошла до приложения. Хук:

- работает в **отдельном потоке** со своим циклом сообщений, а обработчик отрабатывает мгновенно (он только проверяет клавиши и ставит работу в очередь основного потока): если обработчик задумается дольше ~300 мс, Windows молча отключит хук, а пока он думает, тормозит ввод во всей системе;
- реагирует только на `P` и `V` при зажатом правом Alt; всё остальное пропускает не глядя и ничего не записывает;
- помечает свои собственные «нажатия» (`dwExtraInfo = OwnTag`) и не реагирует на них.

**Правый Alt и AltGr.** В раскладках с AltGr (испанская, русская «машинопись» и др.) Windows при нажатии правого Alt сама «нажимает» ещё и левый Ctrl. Эксперимент на живой системе показал:

| Раскладка | События при нажатии правого Alt |
|---|---|
| США | только `RMENU` |
| Испанская | `LCONTROL` со скан-кодом `0x21D`, затем `RMENU` |
| Русская (машинопись) | то же: `LCONTROL` со скан-кодом `0x21D`, затем `RMENU` |

Поэтому хук считает «настоящим» Ctrl только `LCONTROL` со скан-кодом, отличным от `0x21D`, и `RCONTROL`. Сочетание `Right Alt + P/V` срабатывает, если правый Alt нажат, а левый Alt, Win и настоящий Ctrl — нет. Благодаря этому `Ctrl + Alt + P` (в том числе с правым Alt) по-прежнему открывает окно: хук его не трогает.

Состояние клавиш берётся из `GetAsyncKeyState` в момент нажатия `P`/`V`, а не накапливается из событий — так нет «залипших» клавиш, если событие потерялось.

**Маскирующая клавиша.** Если нажать и отпустить Alt, ничего не нажав между, многие программы (Блокнот, Firefox…) откроют меню и заберут фокус из поля ввода. Поэтому, «съев» `P`/`V`, хук сам нажимает и отпускает «пустую» клавишу `VK 0xE8` — тот же приём использует AutoHotkey.

Хук также «съедает» автоповтор и отпускание клавиши; если событие отпускания потерялось, состояние сбрасывается при следующем нажатии.

### Ввод символов (`Typer`)

- Символы вводятся через `SendInput` с флагом `KEYEVENTF_UNICODE`: приложение получает готовый Unicode-символ, а не код клавиши, поэтому текущая раскладка не имеет значения. Браузеры, Блокнот и большинство программ принимают такой ввод как обычное нажатие клавиши.
- Перед вводом поток ждёт, пока физически отпустят Alt, Ctrl, Shift и Win (`GetAsyncKeyState`, до 1,5 секунды), иначе приложение увидело бы `Alt + знак`. Затем ещё 30 мс на то, чтобы приложение заметило отпускание.
- Перед **каждым** знаком проверяется, что активное окно принадлежит тому же процессу, что и в момент нажатия. Если фокус ушёл (скажем, всплыло другое приложение), остаток текста не печатается — пароль не должен попасть не туда. Сравнивается процесс, а не окно: у браузеров активное окно в процессе может меняться (всплывающие подсказки).
- Паузу между знаками делает `Thread.Sleep(typedelay)`. По умолчанию шаг системного таймера — 15,6 мс, поэтому на время ввода включается `timeBeginPeriod(1)`: так 8 мс — это действительно 8 мс.
- Размер структуры `INPUT` зависит от разрядности (40 байт в 64-разрядном процессе): в ней объединены `MOUSEINPUT`, `KEYBDINPUT`, `HARDWAREINPUT`, и объявлять нужно все три.
- `Typer.Clean` готовит текст из буфера обмена: обрезает края, переводы строк и табуляции заменяет пробелом (чтобы настоящий `Enter` не отправил форму), выбрасывает управляющие знаки.

### Сценарии (`TrayApp`)

- `QuickType` (`Right Alt + P`): генерация → запись в файл (описание — заголовок активного окна) → копирование в буфер → `TypeAsync`.
- `QuickType(again)` (`Right Alt + Shift + P`): берёт `lastPassword`, ничего не пишет.
- `QuickPaste` (`Right Alt + V`): читает буфер, чистит текст, проверяет лимит в 500 знаков → `TypeAsync`.
- `TypeAsync` печатает в рабочем потоке и по окончании в основном потоке вызывает `done(problem)`: плашка с результатом. Флаг `typing` (через `Interlocked`) не даёт запустить два ввода одновременно; повторное нажатие во время ввода игнорируется.
- Если активно окно самого генератора, быстрый ввод ничего не делает.
- Ошибки в быстром режиме показываются красной плашкой, а не диалогом: диалог отнял бы фокус у поля, куда идёт ввод.

## Буфер обмена (`Clip`)

Пароль кладётся вместе с форматами `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` (0) и `CanUploadToCloudClipboard` (0): так он не попадает в историю буфера Windows (`Win + V`) и в облачный буфер. Попытки записи повторяются, если буфер занят другой программой.

## Файл паролей (`Storage`)

- Файл открывается с `FileShare.ReadWrite`, поэтому его можно держать открытым в редакторе.
- В новый (пустой) файл сначала пишется BOM. Если существующий файл не заканчивается переводом строки (правили руками), перед записью добавляется перевод строки.
- После записи — `Flush(true)`: запись сразу сбрасывается на диск.

## Неочевидные вещи

- **Подсказка значка в трее — не длиннее 63 знаков.** Иначе `NotifyIcon.Text` бросает `ArgumentOutOfRangeException`, и программа падает при запуске. В коде текст обрезается, а тест переводов проверяет каждый язык, но об этом нужно помнить при правке.
- **Кодировка исходников.** Файлы `.cs` и `.ps1` — UTF-8 **с BOM**, компилятор запускается с `/codepage:65001`. Без этого кириллица превратится в «кракозябры» (на системах с ANSI-кодировкой Windows, отличной от 1251).
- **`System.Windows.Forms.Timer` и `System.Threading.Timer`** — два разных `Timer`; в файлах с обоими `using` нужно писать полное имя.
- **Права на передачу фокуса.** `SetForegroundWindow` разрешён, только если процесс получил последний ввод пользователя. Из горячей клавиши, клика по значку и меню это выполняется; из «искусственных» вызовов других программ — нет.
- **Меню `ToolStrip` не видно в UI Automation** — для автоматической проверки меню пригодился MSAA (`accName`, `accDoDefaultAction`).
- **Запущенный exe нельзя перезаписать, но можно переименовать** — на этом построена подмена файла в `build.bat`.
- **Свежезапущенный exe Windows может держать занятым** какое-то время после завершения процесса (его проверяет антивирус) — отсюда тот же приём с переименованием.

## Что не покрыто автотестами

Автотесты проверяют генератор, подготовку текста и таблицу переводов. Интерфейс, хуки, ввод и фокус проверяются вручную по [чек-листу](../CONTRIBUTING.md#ручная-проверка): они завязаны на реальный рабочий стол Windows (активные окна, раскладки, права процессов), и надёжно автоматизировать их без риска «печатать в чужие окна» не получилось.
